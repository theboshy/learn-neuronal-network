Overview

Neural Self-Driving is a browser-based simulation where a fleet of 1000 cars learn to navigate a road using a feed-forward neural network. There are no hand-coded rules — cars discover how to steer, avoid traffic, and dodge obstacles entirely through neuroevolution: mutate, crash, repeat.

Built with plain HTML, CSS, and JavaScript — no frameworks, no build step, no dependencies. Open index.html in any modern browser and it runs immediately.

Vanilla JS No build step localStorage persistence

How it works

Neuroevolution loop

Every generation starts with 1000 cars placed at the same position, each carrying a mutated copy of the previous generation's best brain. Cars that crash or stop are removed. When the last survivor crashes, the generation ends, the best brain is saved to localStorage, and a new generation begins.

Sensor → Brain → Wheels

Each car casts 10 rays in a 90° arc ahead. Ray lengths (normalized 0–1) feed into a three-layer neural network. Four output neurons drive the wheels.

Mutation

The best brain is deep-cloned for every car in the next generation. Each clone has a small random perturbation applied to its weights and biases (mutation rate: 10%). Over many generations the fleet converges on a brain that can navigate further and further without crashing.

Brain persistence

Each vehicle model stores its best brain independently in localStorage. Closing and reopening the tab resumes training from where it left off. The stored payload includes the brain weights, biases, and the generation number.

Vehicles

Three trainable vehicle shapes, each with its own dimensions, top speed, and independent brain in localStorage. Switching the model tab resets the simulation and loads that vehicle's saved brain (or starts fresh if none exists).

All models share the same network architecture — [10, 6, 4] — so brains are structurally compatible even across models.

Lane-change AI

In addition to the neural network, the lead car runs a secondary lane-change planner. It periodically checks adjacent lanes for clearance and executes smooth lateral moves with turn signals. This runs on top of the network outputs, not instead of them.

Hazards

Obstacles are spawned automatically every 5–10 seconds in a random lane ahead of the lead car. You can also spawn one manually via the sidebar button. Each obstacle type has its own hitbox and canvas drawing — sensors detect them the same way as traffic vehicles.

Class hierarchy

Vehicle is an abstract base class that owns physics, polygon collision, sensors, brain wiring, and the shared draw pass. Each subclass implements two hooks: _drawDetails(ctx) for interior details (windshield, windows, etc.) and _drawWheels(ctx, w, h) for wheel placement. Calling either hook on the base class throws at runtime, making missing overrides immediately visible. 

Vehicle (base)
├─ CarVehicle   — windshield, rear window, roof strip, 4 wheels
├─ MotoVehicle  — seat stripe, handlebar, headlight, 2 inline wheels
└─ BusVehicle   — front windshield, 5 side windows, rear bumper, 6 wheels

Performance

Running 1000 simultaneous physics simulations per frame requires a few deliberate choices.

Batched ghost rendering
Ghost cars are never drawn individually. Their polygons are collected each frame and painted in two single fills — one for alive (green) and one for damaged (red). This replaces ~1000 draw calls with 2.
Off-screen culling
Cars outside the visible viewport are skipped during rendering. Physics still runs for all cars so their brains stay comparable, but no canvas work is done for off-screen ghosts.
Single-pass best car
The lead car (furthest ahead) is found in a single linear scan each frame. No sorting, no array spread — one loop, one comparison.
Lazy brain cloning
The best brain is deep-cloned only when the lead car changes, not every frame. This avoids ~60 JSON round-trips per second.
